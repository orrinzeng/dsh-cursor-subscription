# dsh-cursor-subscription v0.6.11

两处修复针对同一个症状，另加一个针对其结构性原因的开关。观察到的现象是：Cursor 的一轮任务在**反复重推自己的计划**，而不是干活——每一步都重述目标、把目标读回来、重写计划，永远停在第一项，而同一步里的工具调用**每一次都返回了真实数据**。

## 重放会保留每次请求的内容

冷启动——进程重启、桥断、或压缩之后的重建——会把 DSH 历史重放成文本，而工具请求过去只重放成`[Previous tool request: todo_write]` 一个名字。对计划来说，请求**就是**它的参数，于是模型回来时手里没有自己刚写的那张表，只能重新推导一张；同一个缺口也藏起了它已经跑过的检索，这就是同一个调用被重复发起的来源之一。现在每条重放的请求都保留参数（上限 600 字符）：计划完整保留，整文件`write` 则被截断。

这个改动针对的抖动，取自真实会话：15 次 `todo_write`，没有一次与上一次逐字相同；某一轮连续三步重写同一份三项计划，而第一项始终停在 `in_progress`，其中一次还变成了英文。计划抖动主要是"卡住"的症状：计划工具每次调用都整表替换、结果只回计数不回显清单，于是任何改动都是重打一遍；一个推进不下去的 agent，就会去改它唯一还能控制的东西。

## 可选的"每步重放完整历史"

`dsh-codex-subscription` 与本插件只在一处结构上不同，而它正是"同一个会话里 Codex 模型跑完 114 步、Cursor 模型却卡住"的原因：codex 插件走标准 function calling，**历史由它自己组装、每次请求自带**；本插件把历史交给 Cursor 服务端，只发增量。工具面也是同一个差别的结果：Codex 模型只会看到 DSH 的工具，而本插件这边还会被提供 Cursor 自己的工具，只能回绝。

**「每步重放完整历史」**（设置 → Cursor，默认关闭）让每一步都从 DSH 的历史重建会话，而不是沿用Cursor 服务端保存的会话，模型因此拿到与 function calling 适配器同等的、显式的完整历史。之所以默认关闭：Cursor 没有服务端压缩，整段记录会每步重发，token 随步数增长。

触发这个改动的那个 turn：`get_goal` 4 次、`todo_write` 2 次，每一步正文都重述目标；而**同一步里**的 `grep`、`glob`、`read` 全都返回了真实数据——并且 24 步中**一次原生工具都没试过**（中途往返0/24），这排除了"被回绝的工具"这条路径。

## 验证

- **单元测试：** Host 侧 101 项全部通过。本版本新增的两项用例：冷启动的 action 文本里保留`todo_write` 请求及其清单、保留答复它的结果，并且对正文 5,000 字符的 `write` 只做截断、不重放全文；以及开关打开时，手里已有工具结果的那一步会**新建一个 Run**、释放它不复用的桥、把 DSH历史与该结果带进新 Run、并且不去答复被放弃的 exec，同时设置 RPC 往返覆盖该字段并仍然丢弃未知键。
- **未受影响的路径：** v0.6.10 的 resume 路径、沙箱拒绝提示、协议进度行与工具结果处理，测试全部保持通过。
- **抖动（取自真实会话）：** 15 次 `todo_write`，没有相邻两次清单相同；同一份三项计划被连续重写三次；其中一次变成英文。
- **卡死（取自真实会话）：** 在一轮被中断的 turn 里，`get_goal` 4 次 + `todo_write` 2 次，同一步的 `grep`、`glob`、`read` 都返回了数据，且没有发起任何原生工具请求。

## 安装或升级

```sh
dsh plugin --profile web add dsh-cursor-subscription@0.6.11
dsh plugin --profile web list dsh-cursor-subscription --depth 0
```

之后手动重启 DSH，确认 **设置 → Cursor** 显示 `v0.6.11`，并且运行设置卡片里出现**「每步重放完整历史」**。

## 兼容性与已知事项

- 重建开关是"用 token 换显式上下文"：打开后每一步的 prompt 都随整段记录增长，Cursor 侧不会做任何压缩。除此之外不改变行为——同样的工具调用、同样的权限，只是不再复用服务端会话。
- 重放的请求最多保留 600 字符参数。计划能整份保留；文件正文不能，而它的结果本来就在对话记录里。
- 新增设置只有这一个字段。除此之外，运行流、Config schema 与 RPC 面与 v0.6.10 一致。
- 打开这个开关是**实验**，不是默认值：它是本适配器唯一能向 function calling 插件靠拢的地方，代价是每步的 token。如果打开后某一轮仍在重推计划，那原因就不在"历史被委托出去"这件事上。
